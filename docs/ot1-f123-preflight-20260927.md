### Hook 资源条目的同步状态缺失

两应用各有三个 hook 辅助对象：ServiceAccount、Role、RoleBinding。
argocd-self 名称为 atlas-refactor-argocd-redis-secret-init；
envoy-gateway 名称为 eg-gateway-helm-certgen。六个对象均通过单独 GET 确认**仍存在**，
Git 与 live metadata 都带 helm.sh/hook。Argo status.resources 条目有 hook=true、
requiresPruning=true，但省略 status 和 health；通用 ClassifyApplication 将缺失 status
按不等于 Synced 处理，于是标记 BLOCKING_RESOURCES。这里不是普通 App 健康失败，
也不是已删除对象的证明；过程中关于“已删除”的初步推断已由 GET 纠正。

需要在下一修订中明确与锁定 desired hook 生命周期对应的窄分类规则，并验证失败/运行中
hook、非 hook 缺失状态和真正缺失的持久资源仍拒绝。当前没有全局跳过 hook，
没有手工 prune、refresh 或重启。定位：internal/observation/classify.go 的资源状态循环。

### 空 selector 的表示差异

monitoring-ingress 的唯一 spec 差异位于 /spec/ingress/0/from/0/podSelector/matchLabels：

```json
// Git
{"podSelector":{"matchLabels":{}}}
// API
{"podSelector":{}}
```

当前 LiveDesired 只处理已审查 Namespace 默认字段，因此完整 semantic 比较将该差异拒绝。
下一修订需要为已知 selector 的空字段编码建立窄规范化，保持真正 label/expression、
端口和策略变化可见；不能忽略整个 selector 或改成 subset comparison。
本轮没有更改 Git/live NetworkPolicy。定位：internal/ot1/evidence.go 的 LiveDesired 与基线比较。
